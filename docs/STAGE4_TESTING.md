# Приёмка этапа 4

## Что уже проверено автоматически

Сборка debug APK и unit-тесты протокола, счётчиков завершения, учёта входящих файлов и ограничений копирования.
Эти тесты не запускают реальный Nearby и не заменяют проверки Bluetooth/Wi-Fi, Android permissions и сохранения в Room на устройствах.
GitHub Actions выполняет ту же сборку и тесты. Lint не входит в эту проверку; его успешное прохождение не заявляется.

## Подготовка

- Установить одну и ту же новую debug-сборку на оба реальных телефона (Android API 26+, Google Play Services).
- Записать модель, версию Android, версию APK, выданные разрешения и свободное место каждого телефона.
- Использовать тестовые MP3: маленький файл, большой файл, несколько файлов с разными хэшами. Сохранить оригиналы вне приложения.
- A — отправитель, B — получатель; после основных сценариев поменять роли.

## Проверки на телефонах

1. Полный путь: A импортирует MP3 → Send, B → Receive → Accept → выбор → Download → результат. На обоих телефонах итог совпадает; на B треки доступны в Downloaded и воспроизводятся после отключения A.
2. Повтор всей передачи: все треки уже есть на B. Обе стороны показывают 0 переданных и правильное число skipped; ни один телефон не остаётся в ожидании результата.
3. Смешанная передача: часть файлов уже есть на B, часть новая. Новые добавлены один раз, дубли пропущены; итог совпадает у обоих.
4. Отмена на B в середине большого второго файла: первый трек остаётся и воспроизводится, второй не появляется в библиотеке; остаётся результат с числом неудавшихся файлов. После Continue listening можно начать новый сеанс.
5. Повторить отмену на A. Дополнительно проверить системную кнопку Back на экране передачи.
6. Потеря связи: после первого файла выключить Bluetooth/Wi-Fi или отнести телефоны вне радиуса. Нет ложного полного успеха; завершённые треки сохранены. При отсутствии disconnect callback срабатывает таймаут 120 секунд без прогресса.
7. Повторное подключение: Cancel / Continue listening / Send–Receive несколько раз подряд. Нет автоматического принятия чужого запроса, позднего перехода в старый сеанс или удвоения треков.
8. Удалённый файл отправителя: в тестовой установке удалить MP3 через Device Explorer после показа каталога, затем запросить его. Получатель завершает с ошибкой этого файла, не ждёт бесконечно; другие файлы передаются.
9. Повреждённый файл: в отдельной тестовой установке изменить содержимое MP3 отправителя после показа каталога, сохранив размер. Проверка SHA-256 отклоняет файл; на B он не появляется, обе стороны показывают ошибку сохранения.
10. Нехватка места: на выделенном тестовом устройстве запросить набор, которому недостаточно места с учётом временных копий и резерва. Получатель показывает понятную ошибку, библиотека остаётся целой. Не заполнять основной телефон искусственно и не удалять личные данные ради проверки. Исчерпание бюджета непосредственно при копировании дополнительно покрыто unit-тестами.
11. Ручной выбор: оставить B на выборе треков более 120 секунд. Сеанс не обрывается из-за таймаута пользовательского выбора; передача после Download работает.
12. Разные сборки: A с протоколом 1, B с протоколом 2. B показывает просьбу обновить оба устройства и закрывает соединение. Для дальнейшей приёмки установить новую сборку на оба телефона.

На отмене после FILE SUCCESS, но до завершения импорта, готовый файл разрешено досохранить. Результат формируется после завершения таких импортов.
Если A прервал соединение до подтверждения B, число отправленных файлов не означает гарантированное сохранение; проверить библиотеку B. Повтор безопасен благодаря проверке дублей.

## Критерий закрытия

Реализация этапа 4 готова к приёмке, когда сборка и unit-тесты успешны.
Полностью закрыть этап и поставить релизный тег можно после успешного прогона сценариев на двух телефонах и проверки воспроизведения полученных треков.
Результаты устройства фиксировать здесь отдельным коммитом: дата, устройства, SHA коммита APK, пройденные сценарии, обнаруженные ограничения.

## Что не входит в этап 4

Редизайн по Figma, онлайн-аккаунты/сервер, каталог с разбиением на несколько BYTES-сообщений, фоновая передача при выгрузке приложения, автоматическое возобновление после обрыва.
